# Заявки OCTAGON-FIT: почта и серверный журнал

Рабочий обработчик — `mail-api.py` (Python 3, без сторонних пакетов).
`lead-api.mjs` — прежняя Node.js реализация; на действующем сервере она не используется.

## Рабочая конфигурация

- Каталог на сервере: `/home/deploy/octagon-lead-api`.
- `POST https://octagon-fit.ru/api/lead` → Caddy → `127.0.0.1:8792`.
- Отправитель: `podpisait@mail.ru`, SMTP `smtp.mail.ru:465`, SSL/TLS.
- Получатель: `octagon.fit@yandex.ru`.
- Секрет хранится только на сервере в `.env`, права `600`; каталог — `700`.
- `GET /api/health` показывает доступность сервиса и наличие настроек (не проверяет доставку письма).

Все формы: консультация, акции с одним телефоном, запись к тренеру, обратный звонок,
вакансии с резюме. Имя в акционной форме не обязательно. Резюме — до 5 МБ.
В письме передаются тип заявки, контакты, тренер, удобное время, источник и адрес страницы.

## Подтверждение и повторная отправка

Заявка сначала сохраняется в SQLite (`leads.sqlite3`). Ответ `{ok: true, queued: true, id}`
означает, что заявка сохранена; он не означает попадание письма во «Входящие».
Рабочий поток отправляет письмо. Сбой SMTP оставляет заявку в очереди; повторные
попытки продолжаются с увеличивающимся интервалом до часа, включая после перезапуска.
Повтор одинаковых данных в течение 2 минут возвращает тот же ID.

В таблице `leads`: `mail_sent_at` — SMTP принял письмо, `attempts`, `last_error`,
`next_attempt` — состояние отправки. Дополнительно `leads.jsonl` содержит события
`accepted`, `mail_sent`, `mail_failed`. При сбое записи JSONL основным хранилищем остаётся SQLite.
Секретов в журнале нет. Журналы, база и приложения резюме не входят в Git.

Telegram продолжает отправляться отдельно через `forms.a-4-to.ru`. Возвращаемый
`FormRelay.send()` boolean не доказывает доставку в Telegram. Поэтому браузер
показывает успешную заявку только после подтверждения сохранения нашим API;
сбой API больше не скрывается результатом Telegram-релея.

## Развёртывание

Скопировать `mail-api.py` и `mail-watchdog.sh` (под именем `watchdog.sh`) в
`/home/deploy/octagon-lead-api`. Создать `.env` по `.env.example` безопасным способом.
`watchdog.sh` запускает сервис под deploy. Cron пользователя deploy:

```cron
* * * * * /home/deploy/octagon-lead-api/watchdog.sh >/dev/null 2>&1
```

После обновления кода/настроек завершить процесс из `service.pid` и вызвать watchdog.
При перезагрузке сервера cron восстановит процесс в течение минуты.

Caddy маршрутизирует `/api/*` на `127.0.0.1:8792` до статической раздачи сайта.
Конфигурация существующего сайта при обычном `deploy.js` сохраняется.

## Проверка

```sh
curl https://octagon-fit.ru/api/health
```

Для сквозной проверки отправить явно обозначенную тестовую заявку на `/api/lead`,
затем проверить `mail_sent_at` по её ID и наличие письма у получателя.
Принятие SMTP не гарантирует папку «Входящие» — письмо может оказаться в «Спаме».
