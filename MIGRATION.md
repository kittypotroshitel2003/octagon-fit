# Переезд на octagon-fit.ru

Сейчас на домене лежит старый сайт на Tilda. Новый сайт опубликован на
техническом домене `octagon-fit.a-4-to.ru`. Ниже — что сделать до, во время
и после переключения.

## 0. Сайт закрыт паролем

Технический домен `octagon-fit.a-4-to.ru` закрыт HTTP-аутентификацией
(в Caddy — `basic_auth`, логин `octagon`). Пароль передан отдельно, в
репозитории его нет.

Пока пароль стоит, сайт отдаёт `401` всем, включая поисковых роботов:
индексации не будет, карту сайта отправлять бессмысленно.

Снять перед публичным запуском — убрать блок `basic_auth` из
`/etc/caddy/sites/<домен>` и перезагрузить Caddy:

```bash
sudo systemctl reload caddy
```

`node deploy.js` конфиг Caddy не перезаписывает, поэтому обычные публикации
пароль не снимают и повторно ставить его не нужно.

## 1. Можно сделать заранее, не трогая старый сайт

**Яндекс.Метрика.** Счётчик заводится на домен, а не на конкретный сайт.
Создайте его на своём аккаунте и впишите номер в `assets/analytics.js`,
первая строка после комментария:

```js
window.OCT_METRIKA_ID = 0;   // ← сюда номер счётчика
```

Пока стоит `0`, скрипт Метрики не загружается вообще и на сайт не влияет.
Цели `lead_trial` (запись на тренировку) и `lead_job` (отклик на вакансию)
отправляются автоматически из `assets/lead-form.js`.

На старом сайте уже стоят два чужих счётчика — `72008407` и `44120344`.
Один из них, скорее всего, служебный счётчик Tilda. После замены сайта они
перестанут собирать данные. Если один из них ваш и с историей — используйте
его номер, а не заводите новый.

Чтобы не потерять период до запуска, тот же номер можно вставить в настройки
Tilda на старом сайте — тогда статистика пройдёт через переезд без разрыва.

**Search Console и Яндекс.Вебмастер.** Подтверждайте права **TXT-записью
в DNS**, а не мета-тегом: запись подтверждает домен целиком, не зависит от
того, какой сайт на нём лежит, и переживёт переключение. Мета-тег пришлось бы
ставить на старый сайт, а потом переделывать.

Если всё же удобнее мета-тегом — заготовка лежит в `index.html`, в самом
верху `<head>`, раскомментируйте нужную строку.

Карту сайта отправлять **после** переключения: сейчас по адресу
`octagon-fit.ru/sitemap.xml` отдаётся карта старого сайта.

## 2. Переключение

1. Направить A-запись `octagon-fit.ru` на сервер (тот же, где стоит Caddy).
2. Поменять домен в `deploy.config.json`:

```json
{ "domain": "octagon-fit.ru", "type": "static" }
```

Раньше менять не нужно: Caddy не сможет выпустить сертификат на домен,
который ещё не смотрит на сервер.

3. Опубликовать: `node deploy.js`

## 3. Редиректы со старых адресов

Старый сайт проиндексирован, и часть адресов не совпадает с новыми. Без
редиректов эти страницы отдадут 404 и потеряют позиции.

Новости переносить не нужно — они лежат по тем же адресам, что и раньше
(`/news/kak-nachat-trenirovatsya-v-zale-s-nulya` и остальные две).

Остальное добавить в блок сайта в Caddy:

```caddy
redir /schedule  /schedule.html 301
redir /privacy   /privacy.html  301
redir /agreement /privacy.html  301
```

Три страницы старого сайта — служебный мусор Tilda («Quiz Form: Yellow»,
«Copy of…», «Blank page»), переносить и перенаправлять их не нужно, они и так
закрыты в `robots.txt` старого сайта.

`deploy.js` не перезаписывает уже существующий конфиг Caddy, так что правки
переживут следующие публикации.

**Отдельно:** `/agreement` — это не политика конфиденциальности, а отдельный
документ «Согласие на обработку персональных данных». Пока с него стоит
редирект на политику. Если документ нужен на новом сайте — пришлите текст,
страница делается по образцу `privacy.html`.

## 4. После переключения

1. Search Console и Вебмастер → отправить `https://octagon-fit.ru/sitemap.xml`
2. Проверить формы на боевом домене (заявка должна прийти в группу и на почту)
3. Проверить, что старые адреса из раздела 3 отдают 301, а не 404
4. В Метрике убедиться, что данные пошли

## Telegram

Группа клуба: `chatId = -4996440644`, бот `@creatin_sender_bot`.
Значение уже записано в `deploy.config.json`, поэтому **каждый деплой сам
прописывает привязку** домена к группе в `/srv/forms/sites.json` на сервере —
отдельная команда не нужна.

Привязать прямо сейчас, не публикуя сайт:

```bash
node deploy.js --telegram -4996440644 OCTAGON-FIT
```

После переезда на `octagon-fit.ru` привязка применится к новому домену
автоматически при первом деплое: в `sites.json` окажутся оба домена, оба
на одну группу. Записи других сайтов не затрагиваются.

**Если заявки перестанут приходить**, первое, что стоит проверить —
не превратилась ли группа в супергруппу. Это происходит само: при добавлении
некоторых функций, при публикации группы или при росте числа участников.
У супергруппы **другой chat_id** — вида `-100…`. Нужно узнать новый и
выполнить команду выше заново.
